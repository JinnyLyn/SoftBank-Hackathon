## 10/10 도메인 범위 — 먼저 확인할 것

관리형 배포·사용자 독립 도메인이라는 **제품 방향은 확정**이다. 회의록의 백엔드~프런트 목록은 구현 후보이며 신규 구매 자동화 전체가 이번 필수 과제라는 뜻은 아니다. 코드 검증 근거와 SHA는 [PRODUCT_DIRECTION §4](PRODUCT_DIRECTION.md#4-확인한-구현-상태와-검증-범위)에 모았다.

| 항목 | 현재 확인 / 필요한 결정 | 확인할 담당 영역 |
|---|---|---|
| 이번 시연 A/B | 기존 확보 도메인 연결·이전 준비 메모와 프런트의 보유/구매 MOCK은 확인. A 연결 시연 / B 신규 구매 자동화 중 최종 선택·자동화 범위는 확인되지 않음 | 인프라·프런트·백엔드 담당자가 연결 PR에 선택 근거·수동 준비·시험 주소/시각·코드 SHA를 기록하고 진서가 기준 갱신 |
| 연결 계약 | 프런트 `JinVibe:f169d27`의 도메인 API는 제안. 서버 저장 방식·endpoint·상태 enum·프로젝트 연결·실패 후 재개는 합의 필요 | 백엔드·프런트·인프라 |
| 기존 도메인 권한 | 사전 확보 도메인의 사용 권한·등록 주체, DNS 업체·위임 방법·자동/수동 구간. DNS 레코드 안내만 제공하면 지식 부담이 남음 | 인프라·프런트 |
| 신규 구매를 선택할 경우 | 등록 업체·지원 TLD·실제 가격·등록인/동의·중복 구매 방지·갱신/해지·관리/이전 경로. A만 시연할 경우 이 목록을 필수 구현으로 배정하지 않음 | 백엔드·인프라·프런트, 비용·운영 책임자는 별도 확정 |
| 호스트 라우팅·정리 | 공유 443 리스너/호스트 규칙 채택 여부, state 소유권·수동 리소스 관리·할당량·앱 삭제 범위. 일반 destroy가 도메인 해지나 공유 인증서 삭제로 이어지면 안 됨 | 인프라 |
| 비용과 사용자 흐름 | 운영자 AWS 준비 상태를 사용자 연결 화면과 분리. 호스팅 비용 표시·결제 방식, 구매를 지원하면 등록/갱신 비용 승인 | 프런트·백엔드·운영 담당 |

이 표는 확인할 영역을 연결하며 새로운 담당 배정이나 외부 구매·AWS 변경 승인이 아니다. 도메인 기능 미완성을 이유로 독립적인 기존 배포·분석·검사 작업 전체를 중단하지 않는다.

## 10/7에 확인된 내용

- DOCKER 입력은 Dockerfile을 뜻한다. Docker 이미지·실행 중 컨테이너 입력으로 확대하지 않는다.
- 제품 LLM은 우선 Terraform 변수값까지만 바꾼다. HCL 전체 변경은 토요일까지 가능성을 보는 확장 목표다.
- 기술 스택 표에는 HTML·JavaScript, Python·FastAPI, MySQL, AWS가 기재됐다.
- `OLLAMA_API_KEY` secret 이름이 공유됐다. 모델 결정 칸에는 모델을 정한 뒤 적으라고 되어 있다.
- DB 마이그레이션 안건의 결정 칸은 비어 있다. 안건의 체크 표시만으로 확정으로 처리하지 않았다.
- 샘플 백엔드 계약의 참조 위치는 샘플 프런트 README다.

10/9 저장소 재확인: GitHub Actions의 현재 저장소 secret 이름은 `ANTHROPIC_API_KEY`다. 키 값은 확인하지 않았으며, 사용할 모델·호출 경로·SDK·발표자 PC 주입 방식은 별도로 확인한다. 과거 `OLLAMA_API_KEY` 기록을 현재 설정으로 사용하지 않는다.

## 이후 확인할 항목

- 샘플은 Python 3.12·requirements.txt, 프런트는 PR #7의 Node 22.12 이상·npm lockfile을 따른다. 플랫폼 백엔드 PR #10은 Python 3.13.16·requirements.txt·Compose·별도 migration 명령을 제공한다. 초기 CI의 DB 없는 기동 검증과 실제 DB·프런트 통합 검증을 구분한다.
- HCL 전체 변경의 도입 여부와 검증·승인 기준. 10/8에 전체 생성 예시가 있지만 실행 경계 확정 없이 10/7의 변수값 우선 기준을 해제하지 않는다.
- 모듈 수와 추천 방식. 모듈이 하나면 AI가 여러 모듈 중 고른다고 설명하지 않는다.
- 트래픽 변경안을 승인 없이 적용할지에 관한 과거 회의록 충돌. 확정 전에는 제안까지만 한다.
- 로컬 앱의 외부 접근 판정, 개인 코드 재사용, API 비용 지원 여부에 대한 운영진 답변. 10/9 팀 입력 목록의 GitHub URL과 대회 운영진의 입력 허용 답변은 구분한다.
- 제출·중간보고·발표 담당. 10/7 확인 목록에는 있으나 읽은 본문에 결정이 없다.
- 진동현의 프런트 역할은 팀장 초안 기준이다. 10/8에는 AI 구성 추천·배포 코드 생성 담당이 명시됐다. GitHub 계정 매핑은 추측으로 추가하지 않는다.
