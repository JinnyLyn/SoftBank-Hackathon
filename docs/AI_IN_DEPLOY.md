# 배포 과정에서 AI가 하는 일 (발표 준비용 요약)

작성: 진동현 (AI 코드 분석·배포 설정 생성 담당), 2026-10-11 기준 `main`.
구현 위치는 `ai/`(분석기 `ai/runner.py`, 로직 `ai/paved_ai/`)이며 자세한 계약은 [`ai/README.md`](../ai/README.md)에 있다.

## 한 줄 요약

AI는 **업로드한 코드를 읽고 "이 앱을 어떻게 띄워야 하는지"를 찾아 배포 설정으로 정리**한다.
비용 계산·Terraform 계획·실제 배포는 AI가 아니라 인프라 worker 코드가 하고, 실행은 사용자가 승인한 내용으로만 한다.

## 전체 흐름에서의 위치

```
① 업로드 (ZIP / GitHub)                      프런트 → 백엔드
② 비밀값 가리기 → 규칙 분석 → LLM 보완       ◀ AI (ai/runner.py)
   └ Dockerfile이 없으면 초안 작성
③ 구성·비용 비교, Terraform plan              인프라 worker (AI 없음)
④ 비교표·코드 검토·승인                       프런트 (사람이 승인)
⑤ 빌드·배포·헬스체크                          인프라 worker (AI 없음)
```

## AI가 하는 일 (②단계 안의 순서)

| 순서 | 하는 일 | 어디서 | 비고 |
|---|---|---|---|
| 1 | 백엔드에서 분석 안 된 프로젝트를 찾아 소스 ZIP을 받고 SHA-256을 확인 | `ai/runner.py` | 업로드한 원본은 바꾸지 않음 |
| 2 | **비밀값 가리기**: `.env`는 변수 이름만 남기고 값을 모두 가림, 개인 키 파일은 아예 보내지 않음, 코드·설정의 비밀번호·토큰·접속 URL 비밀번호는 `<가림>`으로 바꿈 | `paved_ai/masking.py` | LLM에 보내기 **전에** 실행 |
| 3 | **규칙 분석**: 프레임워크(FastAPI·Flask·Django·Express·Next.js 등), 포트, 헬스체크 경로, Dockerfile 위치, DB 사용 여부, 초기화 명령을 코드에서 찾음 | `paved_ai/analysis.py` | 찾은 값마다 근거(파일:줄)를 남김 |
| 4 | **LLM 보완**: 규칙이 못 찾은 값(포트·헬스체크 경로·Dockerfile 경로·프레임워크)만 LLM에 물어봄 | `paved_ai/llm.py`, `paved_ai/ollama.py` | 규칙으로 다 찾으면 LLM을 부르지 않음 |
| 5 | **답 검증**: LLM 답은 JSON 스키마와 "근거 파일:줄에 그 값이 실제로 있는지"를 확인. 근거가 안 맞으면 버리고 "찾지 못함"으로 남김 | `paved_ai/llm.py` | 추측한 값이 배포 설정에 들어가지 않게 함 |
| 6 | **Dockerfile 초안**: 저장소에 Dockerfile이 없으면 규칙 템플릿으로 초안을 만듦 (Python: FastAPI·Flask·Django / Node: npm·pnpm·yarn). 승인 화면에 보여 주고, 승인하면 worker가 그 내용 그대로 빌드 | `paved_ai/dockerfile.py` | 진입점이 애매하면 만들지 않고 이유를 표시. 소스는 바꾸지 않음 |
| 7 | 결과를 백엔드에 기록: worker가 읽는 `app_config`·`dockerfile`·`scale`과 화면이 읽는 기술 스택·발견 사항·근거·초안 | `ai/runner.py` → `POST /api/projects/{id}/analyses` | 토큰 사용량(`ai.usage`)도 같이 기록 |

## AI가 하지 않는 일

- **비용 계산·구성 추천**: 인프라 worker의 코드(`infra/worker/cost.py`)가 AWS 가격으로 계산한다.
- **Terraform·배포 명령 실행**: worker가 승인된 plan 파일 그대로 적용한다. AI는 명령을 실행하지 않는다.
- **Terraform 코드(HCL) 작성**: 현재 범위는 검증된 모듈에 들어갈 **변수값까지**다(AGENTS.md §4).
- **승인 없이 바꾸기**: Dockerfile 초안도 승인 화면에 그대로 보여 주고, 사용자가 승인한 내용만 쓴다.

## 쓰는 모델과 안전장치

- 모델: Ollama 클라우드 `gemma4:31b` (`ai/.env`의 키로 호출, 키는 저장소·로그에 남기지 않음).
  10/11 같은 문항 6개로 6개 모델을 비교해 가장 빨랐음(중간값 1.2초, 6/6 정답. 비교 대상 glm-5.3 5.6초, kimi-k2.7-code 5.0초 등).
- `temperature 0`, 출력 길이·입력 길이·호출 시간(180초) 상한.
- 같은 입력(가린 코드·프롬프트 버전·모델·설정이 같음)은 저장소 밖 캐시(`~/.cache/paved-ai/llm`)에서 재사용. 검증을 통과한 답만 저장.
- LLM 키가 없거나 호출이 실패해도 규칙 분석 결과로 계속 진행하고, 못 찾은 값은 화면에 "직접 확인 필요"로 표시.

## 발표에서 보여 주기 좋은 장면

1. **비밀값 가리기**: `.env`가 든 저장소를 올려도 분석 결과·LLM 입력에 비밀번호가 없음.
2. **규칙 + LLM 보완**: 포트를 설정 파일·환경 변수 기본값에 숨겨 둔 앱 → 규칙이 못 찾은 포트를 LLM이 찾고 근거 줄을 함께 보여 줌.
3. **Dockerfile 초안**: Dockerfile 없는 저장소 → 초안을 만들어 코드 검토 화면의 "Dockerfile (초안)" 탭에 표시 → 승인하면 그 초안으로 바로 빌드·배포.
4. **분석 진행 표시**: 업로드 직후 단계별 진행 게이지.

## 아직 연결되지 않은 부분 (발표에서 밝힐 것)

- **배포 실패 원인 분석(AI 진단)**: 10/8 분담상 노진서 담당 범위로, 이 문서의 분석기에는 들어 있지 않다.
- 분석기는 아직 `ai/`의 별도 프로세스다. 백엔드가 안정되면 `back/app/llm/`으로 옮길 예정이다.
