# Codex 코드 리뷰 상세 요약

Codex 기본 댓글의 Completed는 리뷰 실행이 끝났다는 뜻이다. 지적이 없거나 코드가 승인됐다는 뜻은 아니다.
이 워크플로는 기존 Codex Code Review의 지적을 PR 대화의 한 댓글로 모아 보여준다.

## 보여주는 내용

- 실행 상태와 최근 리뷰 기록의 커밋, 현재 PR 커밋
- 현재 커밋에 게시된 지적 수와 미해결 지적의 P0·P1·P2·P3 분포
- 각 지적의 제목, 파일·줄, 원문 설명, 원문 대화 링크
- 해결 표시·철회된 리뷰의 지적, 오래된 코드 위치 안내
- 이전 커밋의 지적과 현재 커밋의 리뷰가 아직 확인되지 않았다는 안내

리뷰를 다시 받아도 같은 커밋에 게시된 기존 미해결 지적은 유지한다. 댓글 하나를 갱신하므로 이벤트마다 같은 요약 댓글을 추가하지 않는다.
코드 위치가 오래됐어도 해결 표시가 없으면 확인 대상으로 유지한다.
결론은 게시된 지적과 실행 상태만 설명한다. 실제 코드 수정 여부, 테스트 통과, 사람의 승인 또는 머지 가능 여부를 새로 판정하지 않는다.
긍정 평가·새로운 개선 제안·Security Review 결과는 이 요약의 대상이 아니다.

## 자동 갱신과 수동 갱신

main으로 보내는 PR의 열기·다시 열기·새 push, Codex 리뷰 제출·철회, Codex의 인라인 댓글과 PR 댓글 생성·수정·삭제 때 갱신한다.
일반 사용자 댓글에는 반응하지 않는다. github-actions 봇이 쓴 요약에도 반응하지 않으므로 자동화가 자기 댓글을 반복 처리하지 않는다.

워크플로가 main에 합쳐져야 자동 갱신이 활성화된다. 기존 PR은 이후 이벤트를 기다리거나 수동으로 갱신한다.

1. GitHub의 Actions → Codex Review Summary → Run workflow를 연다.
2. Branch는 main을 선택한다.
3. pr_number에 열린 PR 번호(예: 4)를 입력한다.

GitHub Actions에는 대화의 Resolve / Unresolve만으로 실행되는 이벤트가 없다. 그 상태 변경은 다음 갱신 때 반영된다.
코드 수정 후 새 리뷰가 필요하면 PR에 @codex review를 남긴다. 요약 갱신 자체는 리뷰를 다시 실행하지 않는다.
리뷰 진행·실패 상태는 Codex가 게시한 Code Review 상태 행에서 읽는다. 완료 기록이 없으면 지적이 0건이어도 성공으로 표시하지 않는다.
기존 리뷰 뒤의 재실행도 같은 커밋의 게시된 지적을 집계하므로, 요약의 지적 수를 마지막 실행에서 새로 찾은 지적 수로 해석하지 않는다.

## 권한과 실행 범위

- 추가 AI 호출·API 키·AWS 접근은 없다. GitHub 기본 GITHUB_TOKEN으로 게시된 리뷰와 대화를 읽고 요약 댓글을 쓴다.
- 댓글 작성 작업은 contents: read, pull-requests: read, issues: write만 요청한다.
- 댓글 작성 작업은 PR head 코드를 checkout하거나 실행하지 않고 기본 브랜치의 요약 스크립트를 사용한다. 수동 실행도 기본 브랜치에서만 허용한다.
- 별도의 Codex Summary Check는 PR 코드를 읽기 권한으로 검사한다. 댓글 작성 권한과 비밀값을 제공하지 않는다.
- 외부 Action은 전체 commit SHA로 고정하고 checkout 인증 정보는 남기지 않는다.
- 복사한 설명의 멘션과 HTML은 비활성화한다. 큰 리뷰의 상세 내용이 댓글 길이 제한을 넘으면 생략 안내와 원문 확인 경로를 남긴다.
- REST 리뷰·댓글과 GraphQL 대화 목록을 페이지 끝까지 읽는다. API 요청이 실패하면 작업이 실패하며 새 성공 요약을 쓰지 않는다.
- 갱신 중 PR 커밋이 바뀌거나 PR이 닫히면 댓글 쓰기를 건너뛴다.

기존 Git guard 필수 검사, 사람 승인, 리뷰 대화 해결 규칙은 그대로 적용된다. 새 검사에 대해 최초 CI 성공을 확인하기 전 필수 status check로 등록하지 않는다.

## 검증

~~~text
node --test scripts/codex_review_summary.test.cjs
python scripts/setup_git.py --check
python scripts/test_git_hooks.py
~~~

요약 회귀 검사는 완료와 지적 유무의 구분, 이전 커밋, 재리뷰, 해결·철회·오래된 위치, 멘션·HTML, 긴 댓글, 페이지 처리, 중복 갱신, 커밋 변경 중 쓰기 차단을 검증한다.
검사에서 사용하는 API 응답은 MOCK이다. 실제 댓글 작성 권한과 이벤트 전달은 main에 합친 뒤 첫 실행으로 확인해야 한다.
